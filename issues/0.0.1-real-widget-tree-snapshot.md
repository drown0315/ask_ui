# Issues 0.0.1: Real Widget Tree Snapshot

This issue set breaks the first real Flutter Widget Tree integration into tracer-bullet slices.

Source plan:

- `docs_internal/issues/004-real-widget-tree-integration.md`
- `docs_internal/web-frontend-stack.md`

## Issue 1: Bootstrap Bridge Session From URL

Type: AFK

## What to build

Create the first end-to-end session bootstrap path for Ask UI.

When the page opens with both `vmServiceUri` and `projectRoot` URL parameters, the web UI should create a local bridge session and receive a `sessionId`. When either parameter is missing, the Widget Context Panel should show an incomplete-session state instead of trying to fetch the Flutter Widget Tree.

This slice proves the browser-to-bridge session boundary without fetching real Flutter Inspector data yet.

## Acceptance criteria

- [ ] The web UI reads `vmServiceUri` and `projectRoot` from the page URL.
- [ ] Missing either parameter renders a clear incomplete-session state in the Widget Context Panel.
- [ ] The web UI calls the local bridge to create one session when both parameters are present.
- [ ] The bridge exposes a session creation endpoint that accepts `vmServiceUri` and `projectRoot`.
- [ ] The bridge returns a `sessionId` for a successfully created session.
- [ ] The Widget Context Panel can display creating-session, session-ready, and session-error states.
- [ ] The browser does not connect to Flutter VM Service directly.
- [ ] Existing static workbench layout remains intact.
- [ ] `apps/web` build still passes.

## Blocked by

None - can start immediately.

## Issue 2: Render Real Flutter Widget Tree Snapshot

Type: AFK

## What to build

Use the bridge session to fetch and render the running Flutter app's real Flutter Widget Tree in the Widget Context Panel.

The bridge should own the VM Service connection, configure Flutter Inspector with the provided project root, fetch the Flutter Inspector summary tree, normalize the result into Ask UI Widget Tree nodes, and return that payload to the web UI. The web UI should render the real tree instead of the mock tree when the session succeeds.

## Acceptance criteria

- [ ] The bridge owns the VM Service connection for the session.
- [ ] The bridge configures Flutter Inspector pub root directories using `projectRoot`.
- [ ] The bridge fetches the Flutter Inspector Widget Tree with `isSummaryTree=true`.
- [ ] The bridge does not expose a full-tree or implementation-widget toggle in this slice.
- [ ] The bridge normalizes Flutter Diagnostics nodes into Ask UI `WidgetTreeNode` objects.
- [ ] Normalized nodes use Flutter Inspector `valueId` as `id`.
- [ ] Normalized nodes use Flutter Inspector `description` as `label`.
- [ ] Normalized nodes always include `children` as an array.
- [ ] The web UI renders the real Flutter Widget Tree in the existing Widget Context Panel.
- [ ] Basic fetch errors are visible in the Widget Context Panel.
- [ ] The mock tree is no longer used for successful real sessions.
- [ ] `apps/web` build still passes.

## Blocked by

- Issue 1: Bootstrap Bridge Session From URL

## Issue 3: Refresh Tree Snapshot And Error Recovery

Type: AFK

## What to build

Make the Widget Tree refresh action fetch a fresh snapshot from the existing bridge session and recover cleanly from loading or error states.

Refreshing should reuse the current `sessionId`, treat the response as a new snapshot, and clear any local tree selection. This slice keeps the interaction limited to real tree display; it should not implement `setSelectionById`, selected widget bounds, comments, or agent handoff.

## Acceptance criteria

- [ ] The Widget Tree refresh button fetches a new tree snapshot through the existing bridge session.
- [ ] Refresh does not create a new bridge session.
- [ ] Refresh shows a loading state that does not break the panel layout.
- [ ] Refresh failures show a clear error state.
- [ ] Refresh treats node ids as snapshot-scoped and does not assume they are stable across Flutter rebuilds.
- [ ] Refresh clears any local tree selection for this slice.
- [ ] The implementation does not call `setSelectionById`.
- [ ] The implementation does not read selected widget bounds.
- [ ] The implementation does not create comment targets or staged notes.
- [ ] The successful refreshed tree renders in the existing Widget Context Panel.
- [ ] `apps/web` build still passes.

## Blocked by

- Issue 2: Render Real Flutter Widget Tree Snapshot
