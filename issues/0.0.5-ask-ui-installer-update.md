# 0.0.5 Ask UI Installer And Update Issues

Parent PRD: https://github.com/drown0315/ask_ui/issues/32

## Issue 1: Add Ask UI Version Manifest And Local Metadata

Published issue: https://github.com/drown0315/ask_ui/issues/33

## Parent

https://github.com/drown0315/ask_ui/issues/32

## What to build

Add the version model that lets Ask UI describe a compatible installer, bridge,
runtime, and skill set. The slice should define a version manifest shape, add
local project metadata for the installed Ask UI set, and expose focused parsing
and validation behavior that later installer, update, doctor, and release checks
can reuse.

## Acceptance criteria

- [x] Ask UI has a documented version manifest shape that includes latest,
      minimum supported, installer, bridge, runtime, and skill versions.
- [x] Ask UI has a local project metadata shape for recording the installed
      Ask UI version set.
- [x] Version parsing and compatibility checks are testable without network,
      pub, npm, Flutter, or GitHub access.
- [x] Missing, malformed, mixed-version, and compatible-version cases have
      externally observable test coverage.

## Blocked by

None - can start immediately.

## Implementation status

Completed locally with the bridge `versions` module and focused tests covering
manifest parsing, local metadata parsing, structured validation failures, and
mixed-version compatibility checks.

## Issue 2: Add Bridge Diagnostics For Install Readiness

Published issue: https://github.com/drown0315/ask_ui/issues/34

## Parent

https://github.com/drown0315/ask_ui/issues/32

## What to build

Add an `ask_ui_bridge doctor` path that reports whether a Flutter project is
ready for Ask UI. The command should reuse the version model, inspect the bridge
and target project state that can be checked locally, and return actionable
diagnostics for installer, update, launch, and skill workflows.

## Acceptance criteria

- [x] `ask_ui_bridge doctor` reports bridge, runtime, skill, and project
      metadata status when those values are available.
- [x] Diagnostics distinguish complete setup, missing bridge, missing runtime,
      missing skill, unknown versions, and incompatible version sets.
- [x] Diagnostics output includes actionable messages suitable for humans and
      stable enough for agent-driven workflows.
- [x] Tests cover complete, missing, unknown, incompatible, and malformed local
      state without mutating a real Flutter project.

## Blocked by

- https://github.com/drown0315/ask_ui/issues/33

## Implementation status

Completed locally with `ask_ui_bridge doctor`, JSON diagnostics output, an
injectable skill probe, local runtime and metadata checks, and focused tests for
ready, missing, invalid, incompatible, and invalid-argument states.

## Issue 4: Implement Full Install Bootstrap

Published issue: https://github.com/drown0315/ask_ui/issues/36

## Parent

https://github.com/drown0315/ask_ui/issues/32

## What to build

Make `npx ask-ui install` perform the Ask UI bootstrap for a Flutter project.
It should install or upgrade the bridge, install the selected agent skill, run
diagnostics, write local metadata, and print the next `ask_ui_bridge launch`
command. The installer should not automatically add the `ask_ui_runtime`
dependency to the target Flutter project.

## Acceptance criteria

- [ ] The installer invokes bridge installation through pub global activation
      and reports activation failures clearly.
- [ ] The installer installs the selected coding-agent skill and reports skill
      installation failures without hiding earlier setup results.
- [ ] Successful install runs diagnostics, records local metadata, and prints a
      launch command for the target project.
- [ ] Tests verify command invocation, arguments, partial failures, idempotent
      reruns, metadata writes, diagnostics, and final output using fake external
      tools.

## Issue 5: Support Skill-Only And Skills CLI Fallback Paths

Published issue: https://github.com/drown0315/ask_ui/issues/37

## Parent

https://github.com/drown0315/ask_ui/issues/32

## What to build

Add the workflow-only setup path. `npx ask-ui install --skill-only` should install
the Ask UI agent workflow without touching Dart, Flutter, or local project
dependencies. Skill installation should prefer the public short-name flow when
available and support repository-based fallback when short-name resolution is not
available.

## Acceptance criteria

- [ ] Skill-only install does not run pub activation, Flutter dependency
      changes, or project runtime checks.
- [ ] Skill installation supports the documented agent option and reports
      unsupported agents clearly.
- [ ] Skill installation supports short-name and repository fallback flows.
- [ ] Documentation or command output clearly distinguishes `npx ask-ui install`
      from `npx skills add ask-ui`.
- [ ] Tests cover skill-only setup, short-name install, repository fallback,
      unsupported agent errors, and skill install failures.

## Issue 6: Implement Unified Ask UI Update Command

Published issue: https://github.com/drown0315/ask_ui/issues/38

## Parent

https://github.com/drown0315/ask_ui/issues/32

## What to build

Add `npx ask-ui update` as the main update command for the full Ask UI version
set. The command should update bridge, runtime, skill, and local metadata
together, then run diagnostics so users know whether the updated setup is usable.

## Acceptance criteria

- [ ] `npx ask-ui update` reads the version manifest and local metadata to
      decide what needs updating.
- [ ] The command updates bridge, runtime, and skill through the same external
      mechanisms used by install.
- [ ] The command handles already-current setups as a successful no-op with
      useful output.
- [ ] Partial update failures report what changed, what failed, and what the
      user should do next.
- [ ] Successful updates run diagnostics and refresh local metadata.
- [ ] Tests cover complete update, no-op update, mixed-version update,
      skill-only state, partial failures, and post-update diagnostics.

## Issue 7: Surface Rate-Limited Update Notifications

Published issue: https://github.com/drown0315/ask_ui/issues/39

## Parent

https://github.com/drown0315/ask_ui/issues/32

## What to build

Make normal Ask UI commands surface available updates without blocking valid
work. Diagnostics and launch should perform rate-limited update checks, show the
current and latest versions when an update exists, and tell the user to run
`npx ask-ui update`.

## Acceptance criteria

- [ ] Diagnostics can report an available update from the version manifest.
- [ ] Launch can surface an available update without blocking a valid launch
      path.
- [ ] Update checks are rate-limited so repeated launches do not repeatedly hit
      the network.
- [ ] Offline, unavailable, or malformed update checks do not prevent normal
      local diagnostics or launch behavior.
- [ ] The Ask UI skill workflow delegates setup and update status to
      diagnostics instead of duplicating version logic.
- [ ] Tests cover available update, no update, rate-limited check, offline
      check, malformed manifest, doctor output, launch output, and skill text.

## Issue 8: Document Installer, Skill, And Manual Fallback Flows

Published issue: https://github.com/drown0315/ask_ui/issues/40

## Parent

https://github.com/drown0315/ask_ui/issues/32

## What to build

Update public and package documentation so users understand the three supported
paths: full setup with `npx ask-ui install`, workflow-only setup with
`npx skills add ask-ui`, and manual fallback through pub, Flutter, and skill
installation commands. The docs should also describe `npx ask-ui update` as the
main update path.

## Acceptance criteria

- [ ] User-facing documentation presents `npx ask-ui install` as the recommended
      full setup path.
- [ ] User-facing documentation presents `npx skills add ask-ui` as
      workflow-only skill installation.
- [ ] Manual fallback commands are documented for bridge, runtime, and skill
      setup.
- [ ] Update documentation explains why `npx ask-ui update` is the main product
      update path and `npx skills update ask-ui` is skill-only.
- [ ] Existing skill text is updated to call diagnostics before launch where
      appropriate.
- [ ] Tests or release checks verify that install/update docs and skill text do
      not describe conflicting command boundaries.

## Issue 9: Add Release Validation For Installer Compatibility

Published issue: https://github.com/drown0315/ask_ui/issues/41

## Parent

https://github.com/drown0315/ask_ui/issues/32

## What to build

Extend release validation so the npm installer, bridge, runtime, skill, docs,
and version manifest describe the same Ask UI install and update contract before
a release is published.

## Acceptance criteria

- [ ] Release validation checks that the version manifest matches the published
      installer, bridge, runtime, and skill versions for the release.
- [ ] Release validation checks that skill text and documentation reference the
      current install, update, diagnostics, and launch commands.
- [ ] Release validation fails when command contracts drift between installer,
      bridge, runtime, skill, or docs.
- [ ] The validation can run locally and in CI without publishing to npm, pub,
      or the skills registry.
- [ ] Tests cover valid release layout, version mismatch, stale skill command,
      stale documentation command, and missing manifest data.
