scrcpy WebCodecs Stream 工作原理

这个页面解释当前 test_scrcpy WebCodecs MVP 如何把 Android 设备画面嵌到网页里。 它是能力校准方案：视频走官方 scrcpy 4.0 raw H.264，浏览器用 WebCodecs 解码，点击和滑动暂时走 ADB input。

Android 设备 运行目标 app，系统 display 被 scrcpy server 捕获。
scrcpy-server 通过 app_process 启动，输出 raw H.264 Annex B。
ADB reverse 设备端主动连接 localabstract:scrcpy_<scid> 到本机端口。
Node bridge 接收视频 socket，把字节转成 WebSocket binary frame。
WebCodecs 浏览器拆 Annex B NAL，组装 access unit，交给 VideoDecoder。
Canvas VideoFrame 绘制到画布，形成可点击的设备画面。

一条视频帧大致怎么走

1

设备编码

scrcpy server 从 Android display 取画面，并用设备编码器产出 H.264 NAL。

2

本机接收

Node 先监听端口，再通过 ADB reverse 让 Android server 连回本机。

3

浏览器传输

Node 不解码，只把收到的 raw bytes 放进 WebSocket binary frame。

4

解码渲染

WebCodecs 解码出 VideoFrame，前端绘制到 canvas。

为什么是 raw H.264 Annex B

官方 scrcpy server 开启 raw_stream=true 后，会关闭 scrcpy 自己的设备元数据、帧元数据和 stream metadata。video socket 上剩下的是裸 H.264 Annex B NAL 字节流。

  • 优点：链路短，适合低延迟校准。
  • 代价：浏览器侧必须自己拆 NAL、组 access unit。
  • MSE 不能直接吃这条裸流；MSE 需要先封装成 fMP4。

Node bridge 做什么

Node 在这个 MVP 里负责本地能力边界：选择 deviceId，push 官方 scrcpy server，建立 ADB reverse， 启动 Android 端 server，并把视频 bytes 交给浏览器。

  • Node 不做 H.264 解码。
  • Node 当前只允许一个 raw stream 连接。
  • 断开时要清理 scrcpy process、video socket 和 ADB tunnel。

WebCodecs 做什么

浏览器收到的 WebSocket binary chunk 不是视频帧。前端先按 Annex B start code 拆出 NAL，再基于 NAL type 组装 access unit，最后调用 VideoDecoder.decode()。

  • 从 SPS 里解析 avc1.xxxxxx codec string。
  • 配置 VideoDecoder 时不传 description，让输入按 Annex B 解释。
  • 每个输出的 VideoFrame 绘制后必须 close()。

关键坑：TCP chunk 不是 frame

网络层可能把半个 NAL、多个 NAL、甚至 SPS/PPS/IDR 混在任意 chunk 里发过来。 所以不能把一次 WebSocket message 直接当成一帧给 VideoDecoder。

输入事件为什么暂时走 ADB

当前 MVP

鼠标点击映射到设备坐标后调用 adb shell input tap。 鼠标按住拖拽映射为 adb shell input swipe。

后续方向

正式低延迟输入应校准官方 scrcpy control protocol。那条路线可以承载 touch down、move、up、多点触控、滚轮和键盘。

当前 MVP 限制

  • 只支持 Android。
  • 只支持一个 WebCodecs 页面连接。
  • H.264 parser 仍是校准级实现。
  • timestamp 目前按固定帧间隔生成。
  • 还没有 MSE 或 wasm decoder fallback。

产品化前要补齐

  • 把 session lifecycle 做进 bridge，而不是页面直接管理。
  • 抽出可测试的 Annex B parser 和 access unit builder。
  • 明确 backpressure 和丢帧策略。
  • 补上状态观测：connected、configured、decoded、dropped、queue size。
  • 再校准 scrcpy control protocol。
